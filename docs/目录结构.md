# 仓库目录

```text
DreadHunger-LinuxServer/
├── README.md / README_EN.md       # 快速部署入口
├── docs/                         # Docker、GM 和开服器文档
├── LinuxServer/
│   ├── app/                      # Linux 程序和服务端插件
│   │   ├── dhctl.py
│   │   ├── frida_loader.py
│   │   ├── 开服器/
│   │   ├── GM控制台/
│   │   └── Linux 插件/
│   ├── config/                   # 配置示例，不含真实密码
│   ├── tests/                    # Linux 回归检查
│   ├── install.sh / dhctl.sh      # 裸机部署入口，命令保持一致
│   ├── Engine/ / DreadHunger/     # 自行放入的游戏本体，不提交 Git
│   └── Docker/
│       ├── app/                  # 可独立上传的 Docker 程序副本
│       ├── config/               # Docker 配置示例
│       ├── data/                 # 实际配置、黑名单、日志和运行记录
│       ├── compose.yaml / Dockerfile
│       └── migrate_layout.py
└── WindowsRemote/
    ├── app/                      # 三个客户端、共用代码和客户端插件
    ├── assets/                   # 图标
    ├── build_exe.ps1 / build_quick_join.ps1
    └── dist/                     # 打包结果，不提交 Git
```

Linux 裸机启动仍使用 `./install.sh` 和 `./dhctl.sh start|stop|restart|status`。实际配置沿用原路径：`deploy_config.json`、`开服器/manager_config.json`、`GM控制台/gm_announce.json`，已有密码、黑名单和运行记录无需重建。程序已移至 `app/`，配置模板集中到 `config/`。

直接运行 Python 时，从 `LinuxServer/` 执行 `python3 app/frida_loader.py --root .`、`python3 app/开服器/DreadHungerLinuxManager.py --root .` 或 `python3 app/GM控制台/gm_console.py --root .`。插件优先读取 `app/Linux 插件/`，同时兼容旧部署的 `Linux 插件/`；旧插件的自定义修改和启用状态在升级前备份并合并到新目录。

Docker 程序构建到镜像内，宿主机 `data/` 挂载到容器 `/server`；插件从 `app/Linux 插件/` 单独挂载，面板仍可启停插件。游戏本体继续挂载上一级目录，不重复复制。[Docker 部署与旧目录迁移](Docker部署文档.md)。

Windows 从 `WindowsRemote/` 运行原来的打包脚本；脚本已指向 `app/` 下的源码，输出继续位于 `dist/`。

文档已集中到 `docs/`。真实配置、游戏本体、本地备份和其他未提交的文件会保留；不要通过整目录覆盖或删除来升级。
